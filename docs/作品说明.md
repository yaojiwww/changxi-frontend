## 一、作品概述

**保育通**是一款面向保育师职业资格考试（职业技能等级认定）的移动端备考应用。作品以“学、练、考、评、问”五个环节构成完整学习闭环：用户可以在知识库中系统学习考纲，在每日一练和知识点练习中巩固题目，在模拟考试中还原真实考场，在报告与学习数据中查看掌握情况，并随时向 AI 伴学助手提问。

与传统刷题软件不同，本作品把 AI 深度嵌入备考流程：AI 不只负责“答疑”，还能结合当前备考级别、知识点和练习数据给出针对性讲解与复习规划；同时支持拍照识图提问，把纸质试卷和保育现场照片变成可以直接追问的学习素材。

作品由 HarmonyOS NEXT 客户端与仓颉服务端两部分组成，全部代码自主实现，是一套可运行、可演示、可持续扩展的完整系统，而非静态原型。

### 1.1 作品定位

- **面向人群**：准备保育师初级（五级）、中级（四级）、高级（三级）职业技能等级认定的幼教从业者、转岗人员和在校学生。
- **核心价值**：把分散的考纲、题库、错题、答疑和备考计划收敛到一个应用中，用 AI 降低自学门槛。
- **产品形态**：单机可用的移动 App，联网后获得账号同步、AI 对话等在线能力。

### 1.2 一句话介绍

> 一款“会讲题、会规划、看得懂保育现场”的保育师考证助手。

## 二、背景与需求分析

### 2.1 行业背景

保育师是幼儿园、托育机构中负责婴幼儿生活照料、卫生保健和辅助教育的重要岗位。2021 年，人力资源社会保障部颁布《保育师国家职业技能标准（2021 年版）》（人社厅发〔2021〕92 号，职业编码 4-10-01-03），将保育师划分为五级/初级工、四级/中级工、三级/高级工等等级，并明确了各等级的职业功能、工作要求与理论知识权重。

随着托育服务需求增长，保育师持证上岗成为普遍要求，报考人数持续上升。但备考群体普遍存在以下特点：

- 多为在职人员或转岗人员，学习时间碎片化；
- 理论基础薄弱，尤其对法律法规、卫生保健、心理学等知识感到吃力；
- 缺少专业答疑渠道，遇到不懂的题目只能死记答案；
- 实操经验难以量化，不知道自己“做得对不对”。

### 2.2 现有方案的不足

| 痛点 | 现有做法 | 不足 |
| --- | --- | --- |
| 题库分散 | 纸质题库、网盘资料、小程序 | 题目陈旧、缺少解析、无法沉淀错题 |
| 错题管理 | 手工抄写、截图收藏 | 无法按知识点归类，复习效率低 |
| 答疑 | 搜索引擎、学习群 | 答案不针对考纲，质量参差，响应慢 |
| 实操训练 | 线下培训 | 成本高、频次低、缺少即时反馈 |
| 备考规划 | 凭感觉安排 | 没有目标级别、考试日期和进度依据 |

### 2.3 设计目标

针对上述问题，作品确立了五个设计目标：

1. **体系化**：内容严格对标国家职业技能标准，按级别、职业功能、知识点组织。
2. **闭环化**：学习、练习、考试、评估、提问五个环节互相衔接，数据可以回看。
3. **个性化**：以用户报考级别、考试日期、练习记录为依据，提供差异化内容。
4. **智能化**：用 AI 承担讲解、规划、识图与实操点评，降低自学门槛。
5. **工程化**：前后端分层清晰，接口契约统一，具备持续迭代和真实部署能力。

## 三、系统总体设计

### 3.1 总体架构

系统采用“客户端—服务端—AI 服务”三层架构：

```text
│      │ 用户事件 / 状态渲染                                            │
│      ▼                                                               │
│  viewmodel/    @ObservedV2 + @Trace，承载表单状态与业务编排            │
│      │                                                               │
│      ▼                                                               │
│  api/          认证 / 练习 / 考试 / 错题 / 收藏 / 资料 / AI 七大领域    │
│      │                                                               │
│      ▼                                                               │
│  common/       Http 封装、配置、令牌、按账号隔离的本地存储、工具类       │
│      │                                                               │
│      ▼                                                               │
│  @kit.NetworkKit：http.request（普通请求）/ requestInStream（SSE）     │
└──────────────────────────────┬───────────────────────────────────────┘
                               │ JSON 统一信封 + text/event-stream
┌──────────────────────────────▼───────────────────────────────────────┐
│  仓颉服务端（Spire WebHost）                                           │
│  main.cj 路由 → 控制器 → 业务服务 → 仓储 → MariaDB                     │
│  鉴权 JWT(HS256) · 密码加盐哈希 · 统一响应信封 · SSE 流式转发            │
└───────────────┬───────────────────────────────────┬──────────────────┘
                │                                   │
        ┌───────▼────────┐                 ┌────────▼─────────────┐
        │ MariaDB 10.6   │                 │ Dify 智能体（云端）   │
        │ 8 张业务表      │                 │ 提示词 / 工具 / 多轮记忆│
        └────────────────┘                 └──────────────────────┘
```

### 3.2 技术选型

| 层次 | 技术 | 选型理由 |
| --- | --- | --- |
| 客户端 UI | ArkUI 声明式 UI | HarmonyOS 原生推荐范式，组件化、状态驱动，适配多尺寸屏幕 |
| 客户端语言 | ArkTS | 在 TypeScript 基础上增加类型约束与 UI 能力，工程可维护性好 |
| 状态管理 | 状态管理 V2（`@ObservedV2` / `@Trace` / `@ComponentV2` / `@Local` / `@Param` / `@Event`） | 精确追踪字段级变化，避免 V1 的深度观察限制；跨页状态用 `AppStorageV2` 共享 |
| 网络 | `@kit.NetworkKit` | 原生 HTTP 能力，支持 `requestInStream` 流式接收 |
| 本地存储 | `preferences` | 轻量键值存储，适合令牌、学习记录、进行中考试等结构化快照 |
| 服务端语言 | 仓颉（Cangjie） | 国产编程语言，原生性能与并发模型适合常驻服务，具备工程实践价值 |
| 服务端框架 | Spire | 轻量 WebHost，路由、中间件、依赖注入齐全 |
| 数据库 | MariaDB 10.6 | 关系模型清晰，便于题库、用户、练习记录的关联查询 |
| AI 服务 | Dify 智能体 | 可视化编排提示词与工具，支持流式输出与会话记忆 |

### 3.3 客户端分层

客户端严格执行 **MVVM + 分层**，页面不承载业务逻辑：

```text
entry/src/main/ets/
├── pages/          页面层：只做渲染、路由跳转、Toast 提示
├── viewmodel/      视图模型：表单状态、取数、判题、流式收字、错误处理
├── model/          数据模型：聊天、题库等跨层共享的类型定义
├── api/            接口层：按领域封装后端契约，不直接散落 URL
├── common/         基础设施：HTTP、配置、令牌、账号作用域、本地 Store、工具
├── entryability/   应用生命周期入口
└── model/          跨页面共享的领域模型
```

分层规则：

- 页面层不得直接拼接 URL、解析业务码、做判题或统计；
- ViewModel 失败一律 `throw Error`，由页面捕获后展示，错误文案可直接面向用户；
- 接口路径、请求体、响应体统一收敛到 `api/` 目录，改接口只改一处；
- 跨页共享状态（个人信息、目标级别、考试日期）通过 `AppStorageV2` 连接 `@ObservedV2` 模型，修改后所有引用页面自动刷新。

### 3.4 核心数据流

以“知识点练习”为例：

```text
用户点击选项
   → PracticeViewModel.select()
   → PracticeApi.answer()（判题接口 / 本地题库兜底）
   → 更新答案状态、收藏、错题本
   → PracticeRecord 组装报告并归档学习记录
   → 路由携带报告快照进入 PracticeReportPage
   → 报告页只渲染，不重复计算
```

这条链路体现了三个设计原则：**取数在 ViewModel、判题在数据层、展示在页面**；报告只生成一次并归档；历史报告通过快照回看，保证数据可追溯。

### 4.2 启动与账号体系

- **启动页**：展示品牌标识、吉祥物与 slogan，约 3.2 秒后自动进入登录页。内容可见性由纯状态赋值驱动，并设置 900 ms 兜底定时器，即使动画回调异常也不会出现白屏。
- **登录 / 注册**：手机号 + 密码登录；注册需要 6 位短信验证码，60 秒倒计时防连点；必须勾选用户协议与隐私政策。
- **令牌管理**：登录成功后保存 JWT；后续请求自动携带 `Authorization: Bearer`；业务码 1003 触发全局登出回调，统一清理会话并回到登录页。
- **新手引导**：首次登录进入引导页，设置报考级别（初级/中级/高级）、昵称和考试日期，可跳过（默认初级）。完成标记**按账号存储**，不会因为其他账号点过“跳过”而丢失引导。

### 4.3 首页与备考看板

首页是学习入口的聚合页：

- 顶部问候语随昵称实时刷新；
- 支持切换当前报考级别，专业知识分类随级别联动；
- 基础知识固定展示 10 大类（法律法规、环境知识、安全知识、常见病防治、教育学、生理学、卫生保健、心理学、营养常识、职业道德），合计 2183 题；
- 专业知识按级别展示：初级 1501 题、中级 819 题、高级 498 题，支持展开子分类；
- 主卡片展示总进度与正确率，并给出“接下来练什么”的提示；
- 快捷入口：每日一练、模拟考试、政策解读；
- 展示距离考试日期的倒计时。

### 4.4 每日一练

- 每天固定一套 10 题，同一天多次进入看到同一套题；完成后再次进入直接回看当天报告；
- 每题即选即判，支持收藏、自动记录错题；
- 底部提供上一题/下一题，右上角答题卡可快速跳题；
- 交卷后生成报告：得分、正确率、用时、答题卡、知识点掌握度；
- 提供“再来一组”，在演示题库中循环切组。

### 4.5 知识点练习

- 从首页任一知识点进入，按“章节名 + 当前级别”反查稳定的 `kpId`；
- 题目来源支持“后端题库接口”与“本地题库”双轨：接口不可用时自动退回本地题库，保证演示不中断；
- 判题与解析统一走数据层，页面不持有正确答案；
- 答错自动进入错题本，可随时收藏；
- 交卷后生成练习报告并归档到学习数据。

### 4.6 模拟考试

- 6 套模拟试卷，卡片展示做过人数、是否免费、已考成绩；
- 进入考试后开始 90 分钟倒计时，顶部常驻显示剩余时间；
- **断点续答**：每一题作答都写入本地进行中记录，退出或杀进程后再次进入可继续；
- 答题卡面板支持跳题、查看未答数量、提前交卷；
- 交卷时清空进行中缓存、写入已考记录、生成成绩报告；
- 成绩报告包含：总分、正确率、用时、答题卡、错题解析、分档 AI 评估评语，并可一键跳转 AI 伴学继续提问。

### 4.7 错题本、收藏与重练

- **错题本**：支持全部/近一周/今日/顽固错题筛选，按知识点分组；每道题展示“三次答对”进度（x/3）；三次答对后由数据层判定消除。
- **收藏**：与错题本完全独立，一道题可以同时存在于两处；支持时间范围筛选与按知识点分类。
- **重练**：收藏重练与错题重练共用一套答题页，点选后自动跳下一题，不打断节奏；错题重练结束后统一提交重练结果；收藏页可直接取消收藏。

### 4.8 学习数据与报告

- 每日一练、知识点练习、模拟考试交卷后统一归档为学习记录；
- 学习数据页按时间倒序展示，点击记录可回看当时的完整报告（快照反序列化，不重新计算）；
- “我的”页统计累计答题数、加权平均正确率、学习时长、连续学习天数；
- 所有统计均来自本机学习记录，单条记录损坏时跳过，不影响整体展示。

### 4.9 AI 伴学

AI 伴学是本作品的核心差异化功能：

- **流式输出**：服务端以 SSE 逐事件下发增量文本，客户端边收边渲染，首字到达即上屏，不必等待整段回答；
- **多轮记忆**：每轮保存服务端下发的 `conversationId`，下一轮原样带回，实现连续追问；
- **双模式**：题目解答（`solve`）与专属规划（`plan`），由 Dify 智能体使用不同提示词；
- **拍照识图**：最多一次发送 4 张图片，选图后立即上传换取 `fileId`，本地先按文件头校验 JPEG/PNG/WebP 与 8 MB 上限，避免传完才被拒；
- **知识点上下文**：从 AI 知识库选中知识点后，以胶囊形式显示在输入框上方，发送时把级别、分类、小节、技能要求与知识要求拼入 `query`，用户可随时关闭；
- **容错**：首字延迟高时把读超时放宽到 180 秒；流建立前的失败优先解析统一错误信封，把后端给出的具体原因展示给用户；流中途出错则作为 AI 气泡内容保留，便于回看。

### 4.10 AI 知识库与政策解读

- 知识库内容来自《保育师国家职业技能标准（2021 年版）》，整理为 18 份分类文档，覆盖通用、初级（五级）、中级（四级）、高级（三级）四个分组；
- 每份文档包含若干小节，每节拆分为“技能要求”和“知识要求”；
- 支持级别分组展开、关键词搜索命中、左右分栏阅读；
- 可对整份分类或单个小节发起提问，一键跳转 AI 伴学并自动带入上下文；
- 政策解读页以结构化方式呈现标准的 10 个章节：职业概况、培训参考学时、申报条件、鉴定方式与合格标准、职业道德、基础知识、职业功能、理论与技能权重表、培训与职业禁入等。

### 4.11 AI 实操演练

- 覆盖 6 类保育现场：进餐环节、午睡环境、玩具消毒、盥洗如厕、户外活动、晨午健康检查；
- 用户可从相册选图或拍照，也可使用内置示例照片；

## 五、关键技术实现

### 5.1 MVVM 分层与状态管理 V2

项目全量使用 HarmonyOS 状态管理 V2：

- `@ObservedV2` + `@Trace` 标记可观察类与字段，字段级变更精确触发 UI 刷新；
- `@ComponentV2` 定义组件，`@Local` 管理组件内状态，`@Param` / `@Event` 处理父子通信；
- 跨页面共享使用 `AppStorageV2.connect()`，例如个人信息、目标级别、考试日期在首页、我的、设置之间实时同步；
- 数组更新采用“整条替换”而不是原地修改元素字段，确保 `@Trace` 能观察到变化；
- 流式回答写入聊天列表时，只重建正在生成的那一条消息，其余消息 key 不变，不触发整列表重绘。

### 5.2 网络层与统一契约

- 配置从 `resources/rawfile/app_config.json` 读取，包含 `baseUrl`、`apiPrefix`、连接/读取超时；切换后端只需改这一份配置；
- 所有接口返回统一信封 `{ code, message, data }`，业务码 0 表示成功；HTTP 4xx 时仍优先解析信封，把具体业务原因展示给用户；
- 业务码 1003（未登录/令牌失效）触发全局回调，由 `EntryAbility` 注册，统一清理会话并跳转登录页，避免每个调用方各写一遍；
- HTTP 请求对象在 `finally` 中统一销毁，防止连接泄漏。

### 5.3 SSE 流式对话的工程实现

AI 回答的流式链路是本作品技术难度最高的部分之一，主要解决四个问题：

1. **流式接收**：使用 `requestInStream` 而非普通 `request`，并在发起请求前订阅 `dataReceive` / `dataEnd`，否则响应会被整体缓冲，失去逐字效果。
2. **跨块 UTF-8 解码**：网络分块可能把多字节汉字切成两半。项目实现了一个有状态的 `Utf8ChunkDecoder`，跨块拼接不完整字节，保证不会出现乱码或空串。该实现同时绕开了预览器中 `util.TextDecoder` 被 mock 的问题。
3. **SSE 事件切分**：把 `\r\n` 统一为 `\n`，按空行切分事件块，支持一个事件被拆分到多个 `data:` 行，也处理最后一个事件没有结尾空行的情况。
4. **错误分层**：流建立前的失败返回统一 JSON 信封，客户端解析出 `message`；流建立后的失败只能以 `{"event":"error"}` 事件下发，客户端把原因写入 AI 气泡，而不是一闪而过的 Toast。

### 5.4 多轮会话与知识点上下文

- 每个 SSE 事件都携带 `conversationId`，客户端取到后保存，下一轮请求带回，形成多轮记忆；
- 知识点上下文不影响后端契约：客户端把级别、分类、小节和考点拼成结构化 `query`，后端与 Dify 无需感知新的字段；
- 默认问题与用户自定义问题分开处理，避免“知识点讲解指令”和“我的问题”重复堆叠。

### 5.5 账号级本地数据隔离

同一台设备可能被多个账号使用，若不隔离会把上一个人的收藏、错题、学习记录带给下一个人。项目做了三层设计：

1. **账号键**：从 JWT 的 `sub` 字段解析出用户 ID，形成 `id_<userId>`；解析失败时退回 `phone_<手机号>`；
2. **作用域存储**：`ScopedPrefs` 统一为四个业务 Store（收藏、错题、学习记录、考试）的 key 加账号前缀，并负责旧版本设备级数据的迁移；
3. **会话生命周期**：`SessionService` 收敛三种语义——换号时删除上一账号数据、退出登录只清令牌、注销账号清空当前账号全部数据；避免“个人页和设置页各写一套退出逻辑”导致漏清。

### 5.6 断点续答与报告快照

- 模拟考试每题作答后立即写入本地进行中记录（试卷 ID、答案数组、当前题号、截止时间、开考时间）；
- 再次进入时恢复答案、题号与剩余时间，倒计时以绝对截止时间为准，退出期间不会“暂停计时”；
- 交卷后把完整成绩报告序列化为快照归档，历史回看时直接反序列化，不依赖题库数据变化，也不会重复计算。

### 5.7 服务端鉴权与安全

- 密码使用“SHA-256 + 每用户随机盐 + 12000 轮”哈希后入库，不保存明文；
- JWT 自行实现 HS256 签名与校验，令牌中携带用户 ID；
- 所有业务接口先鉴权，失败返回 401 统一信封；
- 全局异常与 404 由中间件兜底，任何路径都返回 `{code, message, data}`，前端无需为不同错误格式写分支；
- 验证码在开发期打印到服务端终端，便于联调，不返回给客户端。

### 5.8 适配与容错细节

- **安全区**：沉浸式布局下从窗口避让区读取状态栏与底部小白条高度，写入全局 `SafeArea`，各页面按需加内边距，不写死机型和数值；
- **配置加载**：`AppConfig` 全局只读一次，重复调用幂等；未加载时直接抛错，避免拿空地址发请求；
- **图片校验**：按文件头而非后缀判断图片类型，本地先卡 8 MB 上限，减少无效上传；
- **定时器治理**：启动页、验证码倒计时、答题倒计时、实操动画均在页面销毁时清理，防止后台重复跳转或空跑；
- **错误文案**：网络层异常带错误码，业务错误直接使用后端 `message`，用户能看懂、开发者能定位。

## 六、作品特色与创新点

### 6.1 “学—练—考—评—问”完整闭环

多数刷题应用只覆盖“练”，本作品把知识库学习、每日练习、模拟考试、报告评估和 AI 答疑串成一条完整路径，每个环节的数据都能被下一个环节使用：练习错题进入错题本，考试报告可以跳转 AI 追问，AI 知识库可以带知识点进入对话。

### 6.2 AI 与备考场景的深度结合

- AI 不是独立聊天页，而是嵌入知识点、考试报告、错题等具体场景；
- 提问时自动携带报考级别、知识点分类与考纲要求，回答更贴近考试；
- 支持识图提问与多轮追问，能处理纸质试卷、保育现场照片等真实素材；
- 流式输出让“等待回答”变成“边看边想”，显著改善交互体验。

### 6.3 面向真实设备的工程化实现

- 自研跨块 UTF-8 解码器与 SSE 解析器，解决流式中文分块与事件切分的底层问题；
- 账号级本地数据隔离，覆盖换号、退出、注销三种真实场景；
- 断点续答、报告快照、全局令牌失效处理等细节，均来自真实使用中的问题沉淀；
- 前端可配置后端地址，支持本地、预览器、远端服务器多环境切换。

### 6.4 仓颉语言的后端实践

服务端使用仓颉 + Spire 从零搭建，完成路由、中间件、JWT、密码哈希、统一响应、SSE 转发等基础设施，验证了仓颉在 Web 服务场景下的可行性，也为项目增加了技术探索价值。

### 6.5 内容体系严谨

- 知识点与政策内容均来自《保育师国家职业技能标准（2021 年版）》，标注职业编码与文号；
- 题库题目带解析，答案只存在于数据层，页面不持有正确答案；
- 题目 ID 使用稳定业务码，与后端种子数据同码，切换真实接口时不会串数据。

```bash
# 命令行编译（类型检查）
./hvigorw assembleHap

./hvigorw assembleHap --mode release
```

后端地址配置位于：

```text
entry/src/main/resources/rawfile/app_config.json
```

```json
{
  "baseUrl": "http://<服务器地址>:5000",
  "apiPrefix": "/api/v1",
  "connectTimeout": 5000,
  "readTimeout": 10000
}
```

切换本地/远端环境只需修改 `baseUrl`，无需改动代码。

服务端代码位于配套仓库 `changxi-backend`。

**环境要求**：仓颉 SDK、stdx 扩展库、MariaDB 10.6。

```bash
export SPIRE_PATH=<仓库目录>/spire/
export CANGJIE_STDX_PATH=/opt/stdx/linux_x86_64_cjnative/dynamic/stdx
source /opt/cangjie/envsetup.sh

cjpm build      # 编译
cjpm run        # 编译并运行
```

数据库表结构见 `sql/schema.sql`，连接配置见 `appsettings.json`，敏感密钥通过环境变量注入，不写入代码。
